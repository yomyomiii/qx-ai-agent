01개요

양자 개념·코드가 낯선 입문자를 타깃으로 양자 컴퓨팅 입문자를 위한 AI 튜터 학습 환경을 만들었습니다.

핵심 가치 — 학습 흐름이 끊기지 않고 학습 맥락이 자동으로 축적됩니다.

02서비스 컨셉

양자컴퓨팅이 처음인 학습자가 어느 지점에서도 막히지 않도록, 화면을 좌 → 중 → 우 흐름으로 배치해 시작하기 → 이해하기 → 남기기 세 단계 모두 "쉽게" 이어지도록 설계했습니다.

04독자 설계 (레퍼런스에 없는 것)

레퍼런스가 채워주지 못하는 부분을 학습 단계 순서(자료 → 대화 → 회로 → 지식)로 채웠습니다. 학습자가 자원을 준비하고, 대화하며 배우고, 회로를 만들고, 산출물을 축적하는 흐름을 따라갑니다.

📚1단계 — 자료 모으기

학습은 무엇을 들여다볼지에서 시작합니다. 자기 자료를 붙이고, 커리큘럼을 따라가고, 팀원의 지식을 참고할 수 있도록 준비된 공간입니다.

4-1문서 + 회로 통합 소스

먼저, 자료는 문서만이 아닙니다. 문서와 회로 코드를 동급 소스로 다뤄, 체크박스로 선택하면 그대로 AI 컨텍스트로 활용됩니다. NotebookLM이 문서에만 갇히는 지점을 넘어섭니다.

왜: 양자 학습은 개념(문서)뿐 아니라 회로(코드)를 함께 이해해야 하기 때문에, 문서만 다루는 도구로는 회로 관련 질문에 근본적으로 답할 수 없습니다.
서브탭추가 방식예시
📄 문서링크 · 파일(txt/pdf/md) · 직접 텍스트arxiv 논문 · 강의 노트 · 직접 작성 정리
⚛ 회로링크 · 파일(py/qasm/qpy) · 직접 코드저장된 Qiskit 코드 · GitHub 회로 · 팀원 공유 회로
4-2태그 자료 정리

자료가 쌓이면 태그로 정리합니다. 자료 추가 시 자유롭게 태그를 붙이면 카드에 #양자컴퓨팅 같은 chip으로 표시되고, 검색·필터의 근거가 됩니다.

왜: 자료가 쌓일수록 "이거 어디 뒀지?"의 비용이 커집니다. 태그는 자기 언어로 자료를 조직화하는 최소한의 도구이자, 나중에 basis 그래프와 결합되면 관계망을 훨씬 풍부하게 만듭니다.
4-3AI 자료 대화형 추천

없는 자료는 AI가 대화로 찾아줍니다. "AI로 자료 찾기" 버튼을 누르면 자료 탐색 모드로 전환되어, AI가 사용자와 대화하며 논문·회로 레퍼런스를 추천합니다. 결과는 버튼 한 번으로 자료 목록에 추가됩니다.

왜: "이 주제 자료가 어디 있지"에서 시간을 쓰지 않게 하기 위해서입니다.
4-4원클릭 커리큘럼 실습

커리큘럼은 이론과 실습을 하나의 흐름으로 잇습니다. 기초 학습 4개(Bell/GHZ/Grover/VQE)와 도메인 실습 7개가 같은 탭에 있어 자유롭게 왕복하고, 레슨·실습 클릭 시 해당 회로가 편집기에 자동 로드됩니다. 진행은 채팅으로 이어지고 대화 이력이 그대로 저장됩니다.

왜: 이론만 배우면 "언제 쓰지?"에서, 실습만 하면 "왜 이렇게 되지?"에서 막힙니다. 두 서브탭을 자유롭게 오가는 구조로 이론↔실습 왕복이 자연스러워지고, 자동 회로 로드로 학습자가 개념 이해에만 집중할 수 있습니다.
4-5오답 자동 복습

퀴즈에서 틀린 건 그냥 지나가지 않습니다. 레슨별 퀴즈에서 틀린 문제는 오답 복습 섹션에 자동 축적되고, AI가 Q&A로 재구성해 재학습할 수 있게 합니다.

왜: 한 번 풀고 넘어가면 그 개념은 다시 만나지 않기 때문에, 시스템이 오답을 기억해서 재학습을 유도해야 합니다.
4-6산업 도메인 실습

이론은 산업 실습으로 연결됩니다. 금융·보안·바이오·물류·에너지·소재·통신 7개 도메인의 실제 산업 문제를 양자 회로로 푸는 실습을 준비했습니다.

왜: "양자를 왜 배우는가"라는 물음에 답하려면 실제 응용을 보여줘야 하기 때문. 이론·회로·산업이 연결되는 순간 학습 동기가 강해집니다.
4-7팀 스터디 협업

혼자 막히면 팀원의 지식을 참고합니다. 같은 커리큘럼을 공부하는 팀원끼리 질문 게시판과 노트 공유가 있고, 개인 노트를 "팀에 공유"로 노출할 수 있습니다. 모든 질문·공유 노트에 코멘트를 달 수 있어 반응이 이어집니다.

왜: 개인 학습만으로는 막히는 지점이 있어, 팀원의 질문·정리를 열람할 수 있고 거기에 바로 반응(코멘트)을 남길 수 있어야 진짜 협업 학습이 됩니다.
4-8좌측 콘텐츠 채팅 연계

그리고 이 모든 좌측 콘텐츠가 채팅과 연결됩니다. 자료·태그·커리큘럼·팀 스터디이 모두 채팅 컨텍스트로 이어지고, 대화 이력이 그대로 저장되어 노트·요약·마인드맵·실험 보고서 생성의 재료가 됩니다.

왜: 좌측이 자료 저장소에 그치면 매번 열어보고 스스로 정리해야 합니다. 채팅과 실시간 연계되어야 좌측이 학습의 원료 창고가 됩니다.
좌측 콘텐츠채팅으로 이어지는 방식
📄 자료(문서·회로)체크박스 선택 → AI 답변이 즉시 그 자료 기반으로 응답
🏷️ 태그자료 검색·필터의 근거, basis 그래프 확장의 씨앗
📚 커리큘럼 레슨클릭 → 회로 자동 로드 + AI 대화로 개념 안내
🎯 도메인 실습클릭 → 문제 컨텍스트가 채팅에 자동 반영
💬 팀 Q&A · 공유 노트상세에서 "AI에게 물어보기" → 그대로 채팅으로 이어짐
💬2단계 — 대화로 배우기

모아둔 자료가 원료라면 대화는 그 원료를 학습으로 바꾸는 공간입니다. 단순 채팅이 아니라, 컨텍스트에 반응하고 필요한 순간마다 도움을 부르며 결과를 다음 단계로 흘려보내는 허브입니다.

4-9자료 조합별 액션 추천

지금 뭘 물어봐야 할지 시스템이 먼저 제안합니다. 문서·회로 조합에 따라 채팅 입력창 위의 액션 버튼과 추천 질문이 자동 재구성됩니다. 문서+회로일 때만 "이론-회로 연결" 같은 조합 액션이 등장합니다.

왜: "이 자료 조합으로 뭘 물어보지"를 매번 고민하지 않도록, 시스템이 가장 유용한 다음 액션을 먼저 제안합니다. 조합이 성립할 때만 노출되므로 UI가 필요 이상 복잡해지지 않습니다.
자료 조합자동 노출되는 액션 예시
문서 1개자료 요약 · 핵심 개념 · 학습 질문 · 회로 생성
문서 여러 개자료 비교 · 통합 요약 · 학습 로드맵
회로 1개회로 설명 · 개선 제안 · Qiskit 변환
회로 여러 개회로 비교 · 공통 패턴 · 최적 회로
문서 + 회로이론-회로 연결 · 구현 검증 · 개념 보완
커리큘럼 진행 중더 자세히 · 수식 보기 · 다른 방법
4-10상황별 AI 도우미

필요한 순간마다 AI가 그 자리에 있습니다. 학습자가 막히는 지점마다 "AI에게 물어보기" 버튼을 그 자리에 배치했습니다. 도구를 옮기지 않아도 현재 맥락이 자동으로 AI에 전달됩니다.

왜: "AI에게 물어봐야지" 하는 순간에 도구를 옮기고 상황을 다시 설명하는 마찰이 있으면 결국 안 묻고 지나갑니다. 버튼을 그 자리에 두고 맥락은 시스템이 대신 전달해 주면 적절한 타이밍에 자연스럽게 AI 도움을 받게 됩니다.
배치 위치자동 전달되는 맥락
회로 에디터 디버깅현재 편집 중인 회로 (게이트·깊이·구조)
팀 스터디 질문 상세해당 질문 내용
팀 스터디 노트 상세해당 노트 내용
자료 탭 AI로 자료 찾기자료 탐색 모드로 대화 시작
4-11산출물 우측 이동

대화가 끝나면 결과는 우측으로 흘러갑니다. 중앙 채팅에서 만들어진 결과물이 클릭 한 번으로 우측 패널의 시각화 계층에 정착합니다. 회로 코드는 편집기로, 저장된 응답과 자동 노트는 내 노트 목록으로.

왜: 중앙에서 대화·생성 활동이 활발할수록 결과가 흘러갈 곳이 필요합니다. 채팅에만 남기면 스크롤 지옥이 되어 검색·재활용이 어려워집니다. 우측이 시각화된 정착지가 되어야 학습 산출물이 재활용 가능한 자산이 됩니다.
중앙에서 만들어진 것이동 방식우측 시각화
AI 생성 회로 코드채팅 회로 카드의 "에디터에 불러오기"게이트 그리드 + 실시간 시뮬레이션
저장한 AI 응답"메모 저장" 클릭 → 내 노트 목록카드 + 지식 그래프 노드
액션 그리드로 생성한 노트자동 저장카드 + 지식 그래프 노드
🔬3단계 — 회로 만들기

학습의 대표 산출물인 회로를 다루는 단계입니다. IBM Composer가 "회로를 만드는 도구"라면, 우리는 "회로를 배우면서 만드는 도구"가 되도록 편집기 위에 학습 대화 레이어를 얹었습니다.

4-12편집 + 채팅 통합

편집기 위에 챗봇을 얹었습니다. 채팅에서 생성한 회로가 우측 에디터에 로드되고, 에디터에서 "AI에게 물어보기"로 편집 중 회로 상태를 그대로 채팅에 전달합니다. 좌측 컨텍스트는 양쪽에 공유됩니다.

왜: 회로 편집기와 학습 도구가 분리되어 있으면 학습자는 개념과 회로 사이를 왕복해야 하고, 결국 한쪽을 포기하거나 도구를 병행하지 않게 됩니다. 편집 도구 안에 학습 대화를 함께 두면 마우스가 편집기를 벗어나지 않고도 배우면서 만드는 흐름이 성립합니다.

에디터 → 채팅"AI에게 물어보기" → 현재 회로 상태 전달 → 질문·디버깅·개선 요청
에디터 ⇄ 채팅 컨텍스트왼쪽 자료·커리큘럼·팀 스터디이 양쪽에 공유
4-13회로 저장·즉시 편집

여러 회로를 오가며 즉시 편집합니다. 저장된 회로가 카드 목록으로 관리되고 클릭 즉시 편집기로 로드됩니다. 비주얼 컴포저와 Qiskit 코드 두 뷰가 양방향 동기화됩니다.

왜: 학습이 쌓이면 여러 회로를 오가며 비교·수정하게 됩니다. 매번 다시 짜지 않고 저장→호출→편집이 매끄러워야 실습이 학습 자산으로 축적됩니다. 두 뷰 제공은 입문자(비주얼)와 숙련자(코드) 모두를 커버하기 위함입니다.
4-14편집·시뮬·AI 실시간

편집·시뮬레이션·AI가 동시에 반응합니다. 게이트 하나 조작마다 시뮬레이션이 즉시 재계산되고, 디버깅 섹션에서 현재 상태를 요약 확인하며, "AI에게 물어보기"로 원인을 즉답받을 수 있습니다.

왜: 편집 → 실행 버튼 → 결과 확인 → 편집으로 되돌아가는 사이클이 길수록 학습자는 왜 그렇게 됐는지 감을 잃습니다. 편집과 검증이 실시간으로 붙어 있어야 "이 게이트를 추가하니 얽힘이 사라지네" 같은 인과 관찰이 즉시 가능합니다.
도구실시간 동작
시뮬레이션게이트 조작 즉시 상태벡터·확률 분포·엔트로피·얽힘 재계산
디버깅 섹션편집기 하단에서 현재 회로 상태 요약
AI 호출"AI에게 물어보기" → 현재 회로 상태 그대로 AI에 전달
4-15회로 나란히 비교

다른 회로와 나란히 비교합니다. 시뮬레이션 섹션에서 "회로 비교" 토글로 현재 회로와 저장된 다른 회로를 같은 축으로 표시해 확률 분포·상태벡터를 시각적으로 대조합니다.

왜: 회로의 미세한 차이가 결과에 어떤 영향을 주는지 확인하려면 두 회로를 나란히 놓고 보는 것이 가장 빠릅니다. "H 위치를 바꾸면 어떻게 되지?" 같은 실험이 즉시 시각화됩니다.
4-16회로 출처 자동 태깅

회로도 출처를 갖습니다. 저장되는 모든 회로에 🔖 AI 응답 / ⚛ 샘플 / ✏️ 직접 작성 태그가 자동 부여됩니다. 이 원칙은 노트에도 확장됩니다(4-18).

왜: 복기할 때 "이건 내가 짠 건가, AI가 준 건가, 샘플인가"를 즉시 판단할 수 있어야 복기·재활용 흐름이 자연스럽게 이어집니다.
source 태그의미자동 부여 시점
🔖 AI 응답채팅에서 AI가 생성한 회로채팅 → 에디터 로드 시
⚛ 샘플커리큘럼 레슨 / 자료 탭 회로레슨·자료 클릭 시
✏️ 직접 작성컴포저·코드로 사용자가 편집사용자 편집 시
📝4단계 — 지식으로 남기기

마지막으로 학습의 축적물이 자라는 단계입니다. 회로와 노트가 각자 저장되고 서로 연결되어, 시간이 갈수록 지식 그래프가 자란다는 것이 핵심입니다.

4-17AI 노트 자동 생성

여러 입력을 조합한 통합 노트를 만듭니다. 대화 → 요약·마인드맵·용어정리, 회로 → 분석·비교, 회로 + 대화 → 실험 보고서 등 6가지 유형이 자동 생성됩니다. 실험 보고서는 문서만 다루는 NotebookLM으로는 원천 불가입니다.

왜: 단일 소스 요약만 가능하면 "이 실습에서 뭘 배웠지"라는 통합 회고를 결국 사람이 직접 해야 합니다. 여러 입력을 조합해 통합 결과물을 만들어 학습자의 회고 부담을 줄입니다.
노트 유형필요한 입력생성 결과
대화 요약 📝전체 대화핵심 5개 이내 bullet
용어 정리 📖전체 대화등장 용어별 정의·설명
마인드맵 🗺️전체 대화개념 트리 (들여쓰기)
회로 분석 🔬회로 1개동작 원리·최종 상태·활용 맥락
회로 비교 📊회로 2개 이상게이트 구성·목적·결과 차이
실험 보고서 📋회로 + 대화실험 목적·구성·관찰·배운 점
4-18노트 자동 연결

노트도 태어난 시점부터 출처를 갖습니다. 4-16의 회로 출처 원칙과 짝을 이뤄, 노트가 어떤 회로·어떤 대화에서 왔는지 basis 필드에 자동 기록됩니다. 사용자가 별도로 링크를 그리지 않아도 됩니다.

왜: 노트가 어디서 왔는지가 남아 있어야 나중에 "이 정리가 어떤 회로/대화에서 나왔지?"를 되짚을 수 있습니다. 이 출처 데이터는 다음 항목(4-19)의 지식 그래프 원료가 됩니다.
노트 유형자동으로 붙는 basis
대화 요약·마인드맵·용어 정리전체 대화
회로 분석⚛ {회로 이름}
회로 비교⚛ {회로 A} · ⚛ {회로 B}
실험 보고서⚛ {회로} · 대화
직접 작성 메모사용자가 선택한 참조
4-19지식 그래프 자동 생성

그래서 지식 그래프가 자동으로 자랍니다. 노트의 basis와 회로의 source를 원료로 Hub-and-Spoke 그래프가 자동 구축됩니다. Obsidian처럼 수동 백링크가 필요 없고, 앞으로 자료·태그까지 그래프 노드로 확장될 예정입니다.

왜: 학습이 쌓일수록 "이 개념·회로·노트가 서로 어떻게 연결돼 있는지"가 흐릿해집니다. 입력 시점의 규칙 하나(source·basis 자동 기록)가 뒤의 모든 관계 시각화·검색·재활용을 가능하게 합니다.
